# 50011：A–E 诊断自动接管连接

## 已确认的流程缺陷

50010 的 `DiagnosticPorts.claim()` 在普通会话连接中、已连接或正在收尾时，直接抛出“请先停止普通连接，并等待旧任务退出，再开始综合诊断”。蓝牙自动连接可能在用户手动断开后重新占用会话，导致再次点诊断仍被拒绝。

同时，蓝牙 ACL 断开通过普通 `disconnect()` 路径处理；诊断占用连接时，该方法会调用批次 `cancel()`，把自动切换期间的蓝牙事件误当成用户点击停止。

这两处都是应用流程问题，与手机 Activity 102 或 CarLife 视频内容无关。

## 修复

- 点击开始诊断，先在与普通连接相同的互斥边界取得诊断所有权，阻止普通连接抢占；再自动取消旧连接、等待旧任务/原生引擎/编解码器退出并取得前台保活。
- 失败或取消时，以不可取消的收尾流程完成退出并释放所有权。重复请求不能停止另一份正在运行的诊断。
- 诊断期间的蓝牙连接/断开只更新观察信息，不触发普通连接，也不取消批次；实际连接故障仍由会话、心跳及每例超时处理。用户点击“停止”仍然能取消。
- 界面显示“开始视频诊断（自动接管）”；来源预览确认与开始 A–E 合并为一个操作。无需回首页手动断开，蓝牙和车机 Wi-Fi 保持开启。
- 原厂授权、来源预览确认、本地解码验证、每轮人工画面标记、失败/取消不计通过等保护仍保留。若车机自身弹出授权或选择提示，仍需用户在车机确认。

## 验证与边界

- 新增所有权测试：已连接会话接管、旧任务未退出前屏蔽自动事件、重复请求、取消中收尾、保活失败回滚、同一异常重复出现时也能释放所有权。
- 完整控制流程测试：普通连接存在时开始预检；普通自动连接在两阶段之间再次建立；随后运行 A–E，逐轮记录黑屏结果，确认五轮都能推进，蓝牙事件不取消批次，过程无手动断开。
- 本次不修改 Rust 或编解码协议；沿用 50010 已验证的 arm64 库，源码树和库哈希核对一致，未重复声称执行 Rust 测试。
- 本地无 Android 模拟器，手机未连接；实际点击、系统蓝牙事件和 MIB3 车测仍待验收。主代理自审，没有独立子代理审查。
- 最终 Android 测试、Lint、签名、对齐、APK 哈希及源码提交记录见 `docs/artifacts/v50011.json`。

## 操作

停车后打开「诊断 → 一次安装综合诊断」，点击“开始视频诊断（自动接管）”。等预检完成，若预览确为正常 Jovi 桌面，点击“预览正常，开始 A → E 车测”。以后只需按实际车机画面选择结果，程序负责每轮结束和下一轮连接；结束后导出 ZIP。

50011 修复的是诊断入口及自动连接冲突，不代表此前黑屏或音频断续已经实车验收。
