# 与 cardeck 的差异对照（2026-10-25）

参考：`shaonialife/cardeck` 的 `docs/PROTOCOL-NOTES.md` 与
`airplay/PairingClients.kt`（MIT/Apache 许可的二创项目，协议结论来自奥迪/宝马实车 + 真机抓包）。
本文只记**我们和它的差异**，逐条标状态，避免以后再走回头路。

## 1. 配对身份模型

| 项 | cardeck | 我们 | 状态 |
|---|---|---|---|
| 身份内容 | `ControllerIdentity(pairingId: UUID, ed25519 私钥, 公钥)` | 相同（`pairing.rs`） | ✅ |
| 生成时机 | 首次使用时生成，之后**持久化复用** | 相同（`controller_identity.txt`） | ✅ |
| 身份丢失后果 | 车机认为是新设备 → 只有两边删配对才能恢复 | 同（2026-10-25 现场复现） | ✅ 已确认 |
| 日志可归因 | 未特别记录 | 现在每次连接打 `PAIR: 复用身份 pairingId=… pub=…`／`⚠ 新建身份` | 🔧 0.1.0.61 |
| 身份备份 | 未做 | **文件 + SharedPreferences 双写**：文件丢失自动写回，不重新生成 | 🔧 0.1.0.62 |

> 关键结论：**身份必须跨会话稳定**。车机记住的是 pairingId + 公钥；
> 一旦我们重新生成，"第二次上车连不上"就是必然结果，和网络/协议都无关。

## 2. 配对流程（pair-setup / pair-verify）

| 项 | cardeck | 我们 | 状态 |
|---|---|---|---|
| 首次 | `POST /pair-setup` M1→M6（SRP-6a，码 `"Pair-Setup"/"3939"`） | 相同 | ✅ |
| M6 校验 | 校验接收端身份签名 | 相同（日志 `签名校验=true`） | ✅ |
| 之后 | `POST /pair-verify` M1→M4（临时 X25519 + 长期签名） | 相同 | ✅ |
| 已配对设备的第二次连接 | 走 verify 快路径；我们**以前每次都先 pair-setup** | 改成 **verify 优先**，失败才 setup（且换新连接） | 🔧 0.1.0.60 |
| setup 被 403 | 换**新 TCP 连接**再 verify（旧连接状态机已污染） | 相同 | ✅ |
| 老车机不支持配对 | 404/405/455/501 → 明文 et=NONE 会话 | 相同 | ✅ |

## 3. 蓝牙：让车机识别成「CarPlay 设备」而不是「普通手机」

| 项 | cardeck | 我们 | 状态 |
|---|---|---|---|
| HFP/A2DP | **只配对、不连接**；发 iAP2 前若已连则先断开 | 档案开关 `dropProfilesBeforeIap2`；**宝马档案原来是 false**，现改 true | 🔧 0.1.0.60 |
| 拆链时机 | 不要频繁拆（每 3s 拆一次会持续扰动车机） | 只在 iAP2 启动前拆一次 | ✅ |
| 会话期间 | **不断 BT**（断了车机会收起 CarPlay 窗口） | AirPlay 期间不再因 ACL 断开而拆会话 | 🔧 0.1.0.59 |

## 5. iAP2 消息细节（宝马相关）

| 项 | cardeck 记录 | 我们 | 状态 |
|---|---|---|---|
| `0xEA00` 的 param 1 | **必须是 EA 协议名字符串**（如 `com.bmw.carplay`），不是协议号 | 已发字符串 | ✅ |
| 设备状态问候 `0x4E0D/4E0C/4E0A/4E0B/4E09` | **紧跟 `0xAA05` 立刻突发**（原来排在等 0x5703 之后 → 车机 5s 拆链） | 已紧贴 AA05 | ✅ |
| `0x5702` | 必备，清单没声明也要发 | 发（1.5s 窗口，未到则重发一次） | ✅ |
| `0x4300` / `0x4E0E` | 发后不管（不 awaitAck） | 相同 | ✅ |
| `0x4E0C` 无线会话标识 | 每次会话随机大写 UUID | 相同 | ✅ |
| 主动结束会话 | **不要**（会让车机收起 CarPlay 图标） | `abortWhenCarPlayWindowClosed=false` | ✅ |
| 链路 marker / SYN 协商 | 每条纯 SYN 都要回 SYN|ACK；SYN-ACK 必须推进序号 | 已按此实现（含单测） | ✅ |

## 7. 我们仍然缺的（⏳ 待办）

1. **身份导出/导入 UI**：跨「卸载重装」保住配对（现在只保「文件丢失」，保不了清数据/重装）。
2. **`0x5702` 是否要带参数**：cardeck 也未定（他们发空体，奥迪接受）；需要一次真 iPhone 同车抓包定参数号。
3. **宝马 `RECORD` 之后的解码确认**：目前还没到推流成功，先按 §6 的头部字段保证，若黑屏再抓包对照。
4. **`0xEA03` 从不回**：宝马声明会发却始终不发；cardeck 也有同样观察，暂列为车机行为。

## 8. 一句话总结

cardeck 最有价值的两条经验，我们之前**都没做**、现在都补上了：

- **身份必须持久稳定**（否则第二次上车必失配，只有两边删配对才能恢复）；
- **发 iAP2 前必须断开 HFP/A2DP**（否则车机把你归类成普通手机，不给 CarPlay 窗口）。

其余协议细节（EA 名字串、问候时机、modesChanged、三条心跳、VideoConfig 头）我们本来就已对齐。
