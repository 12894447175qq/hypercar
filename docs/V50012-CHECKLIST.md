## 第二轮：具体原因和修复归属

### 本轮新增修复

1. **蓝牙广播误取消整个连接。** 普通会话的 ACL 断开调用 `disconnect()`，关闭 CarLife、停止原生引擎、取消来源恢复并设置“用户主动停止”。改为仅关闭失效 RFCOMM，不清除车机身份，也不改变用户停止意图。Wi-Fi 丢失、AirPlay 控制/心跳失败和有限协商超时继续负责实际断线，手动停止仍立即取消。
2. **Audi 的 AirPlay 激活后继续重新争抢蓝牙。** 之前 RFCOMM 一结束就重新拨号，还可能再次断开 HFP/A2DP。现在只在 Audi MIB3 完成 `RECORD` 后结束本轮新蓝牙连接获取，保留已建立的 iAP2 通道；新的入站连接不能替换已有会话，正在拨号的 socket 可关闭取消。完整断线重连会创建新的获取状态，不会永久禁止蓝牙。
3. **拨号与已接入通道共享 socket 所有权。** 以前未完成的出站连接直接写 `currentSocket`，可能覆盖入站会话。现在待拨号 socket 单独持有，最终会话接管在互斥边界内决定，旧拨号的迟到退出不能释放新的 socket。
4. 配置文件查询、等待断开和设备级兜底之间复查当前连接状态；Wi-Fi 接管后不继续后续断开动作。已经交给 Android 的系统调用不能撤回。日志区分“请求断开”与“确认已断开”，不会在停止获取后仍声称正在蓝牙重连。

影响范围：新建连停止策略仅在 Audi MIB3 激活时启用；BMW、通用及其他档案保留原建连策略。ACL 与 Wi-Fi 分离适用于普通会话；综合诊断继续独占连接，用户停止不变。未修改 Rust、vivo/Jovi 入口、六端口 UID 核验、加密协议、原厂权限或组件启用状态。

### 已有修复保留，不能当作本轮新发现

- 50010：可见 Activity 优先启动来源、102 分类、完整来源退出后有预算重连；音频短缓冲及迟到不突发追发；Audi＋vivo 默认 Level 4.0＋关键帧内参数；普通连接自动保存短视频证据。
- 50011：综合诊断自动接管普通连接，蓝牙事件不再取消诊断批次。
- 用户显式保存的视频策略仍优先；默认兼容策略不覆盖已保存的选择。

## 普通车测即可收集关键证据

无需先跑 A–E：选择 Audi MIB3、来源 `com.baidu.carlife.vivo`，启用 CarLife 联动，手机前台打开 Hypercar 后按普通连接使用。若之前保存过其他视频策略，要留意实际策略；不要把关闭 CarLife 的等待页测试当成取源测试。

普通 vivo 连接会自动保存来源端及发送端的短样本（各最多 90 帧 / 8 MiB），不自动上传。停车结束连接后，在「诊断 → 一次安装综合诊断」导出对应 `batch-auto-…` 历史批次 ZIP，附同次 TXT。只导出即可，无需再次开始 A–E。这一对样本可在电脑上直接解码比较，区分来源已经黑、发送转换异常、以及车机接收显示异常。
