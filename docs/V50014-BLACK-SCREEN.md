# 50014：等待页切换到 vivo/Jovi 的视频参数与恢复修复

本版修复了两处可以在生产视频泵中复现的缺陷：异步尺寸回调覆盖真实 SPS，以及来源断开后沿用旧 SPS/PPS。保留 `com.baidu.carlife.vivo`、原厂组件、六端口 UID 归属检查和既有连接流程。没有改成自绘车机桌面，也没有默认启用硬件转码。

**尚不能宣布用户的黑屏已解决。** 当前仍只有 2026-10-29 的 50009 TXT，没有当次来源视频或新的实车结果。旧日志中两次来源配置本来就是正确的 1280×720，本轮尺寸竞态并不能解释那两次黑屏的全部原因。

## 参考资料的适用范围

参考固定在 CarPToCarL 提交 `4e42a0d23ee411a1ac4d2ffa44feef9d9fca726d`：

- [MIB3H SW 3874 固件分析](https://github.com/jjuugk/CarPToCarL/blob/4e42a0d23ee411a1ac4d2ffa44feef9d9fca726d/docs/mib3-firmware-3874.md)是项目作者整理的静态分析，用户照片为 SW 3695，不能当作这台车的实测规范。
- [VideoSender.kt](https://github.com/jjuugk/CarPToCarL/blob/4e42a0d23ee411a1ac4d2ffa44feef9d9fca726d/app/src/main/java/io/github/shaonialife/carptocar/video/VideoSender.kt)的 `sendConfigFromNals` / `resolveConfigSize` 默认以同份 SPS 的可见尺寸构造解码配置，显示视口是另一组字段且默认不写。这比旧文档“按 /info 画布强制匹配”的概括更具体。本版按码流声明尺寸，不把 1280×720 假报成 1412×654。
- 当前参考实现有跨来源缓存 CSD 的兜底。本版没有照搬：新的来源 TCP 连接不能证明还是旧编码器，必须重新收齐 SPS/PPS/IDR；同一来源连接内的缓冲溢出仍可保留参数等待新 IDR。这也意味着新连接若始终不提供参数，仍会停在等待页，不能标记恢复成功。

## 实现与影响

1. `SourceVideoBuffer` 以当前 GOP 的 SPS 决定尺寸；CMD 回调只作为解析不可用时的兜底。晚到回调不再清空合法 GOP。`ScreenSender` 从同份 SPS 校正 VideoConfig，避免其他入口错配。硬件转码入口复用该尺寸，不再维护另一份可被回调覆盖的状态。
2. 来源断开清空 SPS、PPS、参考帧；心跳写失败也发出来源断开事件。等待页与来源参数分离，恢复时先配置再发本轮 IDR。屏幕连接的加密计数器和单调时间继续使用，不随切源归零。
3. 增加限频的 `source_gate=waiting`、`source_geometry`、`source_size_hint`，以及 `decoder_contract`、`sourceEpoch`、每次来源重连的 `first_source_frame_written` 日志。明确区分“缺参数”“参数契约”“已写出”和“实车显示尚未验证”。这些日志沿用现有文件日志和导出机制。

## 验证

- 修复前：5 项生产泵 TCP 回归中 2 项失败，准确覆盖上述尺寸与旧参数问题。
- 修复后：`cargo check --locked` 通过，完整 Rust 测试 **66 项通过**；Android JUnit **130 项通过**；Lint **0 错误、30 警告、2 提示**，数量与上一版一致。
- 真实 TCP、ChaCha 认证解密、配置头、连续计数器和单调时间均被测试读取；同尺寸切换、跨尺寸切换和回调乱序三组输出经 FFmpeg 独立解码，来源分别 18、18、9 帧，逐帧像素与原始测试源一致，混合等待页输出也能解码。
- 四种软件视频策略另经生产泵、TCP 和认证接收端回放，FFmpeg 各解码 9 帧，像素均与测试源一致。
- 使用旧日志的真实 SPS/PPS 验证 1280×720 配置、Baseline、现有 Level 4.0 策略、内联参数和加密标志一致。该项使用合成 slice 只验证封装，不能声称复原或解码了用户视频。
- arm64/API31 原生库重新编译。最终 APK 版本、签名、哈希、JNI、源码提交和 16 KiB 对齐核验结果见 `artifacts/v50014.json`。
- 主代理自审；没有独立代理审查。心跳写失败事件分支经静态审查，未单独注入真实 socket 心跳写故障。FFmpeg 输入是生成的可解码测试流，不是当前 vivo 的采样。

手机安装、Jovi 桌面实际内容、Android 硬件解码/转码、MIB3 画面/声音/触控及真实重连都尚未执行。仍需区分来源已黑与接收端不显示，不能用通过的本地测试代替这一结论。

## 车测方式

安装 50014 后，保留 Audi MIB3、vivo 来源和 CarLife 联动设置，正常连接即可，无需跑 A–E。若以前保存过手动视频策略，可点一次“恢复默认视频策略”；已恢复过则不用重复。看到等待页、黑屏或 Jovi 桌面时记录现象。停车结束连接后导出普通 TXT：既有 `VIDEO-CONTENT` 会对最近完整来源样本分析近黑像素；本版新增日志会显示参数和来源代次。若仍有黑屏，附上同批次诊断 ZIP，才能进一步核对真实来源与输出像素。
