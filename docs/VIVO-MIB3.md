### 1. 21:08 有来源帧，21:09 断开

- 21:08:33.969 来源回报实际编码尺寸 `1920×720`；屏幕流稍后就绪。

  旧代码把它当作毫秒，再直接转换为车机视频 NTP；计时服务却使用进程单调钟，二者时间基不一致。
  这是可确认的代码缺陷，但旧日志未记录每个出站头，不能证明它独自导致此次断开。
- 首批来源数据早于屏幕泵就绪，旧实现直接丢弃；有丢失 SPS/PPS/IDR 的风险。

- 21:09:00.939 的统计为 190 帧；旧计数还把 `Ok` 但实际未写出的视频算在内。
  它不能证明车机解码成功，也不能证明来源已经是可操作桌面。
- 21:09:02.686 的错误被固定改写为“车机侧断开”，底层错误已丢失，无法补推出 errno。

### 3. 旧会话结束后仍连接来源

21:13:08.747 已清理并断开，21:13:10.606 却再次收到 `carlife_active`；21:14 新引擎启动前
也出现旧 CarLife 握手。这证明旧任务残留，且旧回调会被当前 TRACE 错误归属。

旧实现只发送瞬时 Notify，不等待退出；深层 read、重试 sleep 可能漏掉停止信号。
计时 UDP 任务还会因丢弃 JoinHandle 而脱离管理。另有 Java 层永久保存 Socket 的缺陷：
本应用 minSdk=31，而 Android 29 后 `fromSocket/fromDatagramSocket` 已复制描述符，保留原句柄
会使 Rust 关闭副本后连接仍存活。
[Android 描述符契约](https://developer.android.com/reference/android/os/ParcelFileDescriptor#fromSocket(java.net.Socket))
明确要求两个所有者分别关闭。

修复：持续有效的会话取消状态、子任务统一登记和退出屏障；新引擎接触来源前等待旧任务全部退出；
原生与 Kotlin 启停串行化，每轮回调携带编号，旧回调和过期重试无法更改新会话；UDP 随会话销毁。
交出复制的描述符后立即关闭 Java 原句柄，取消或配置失败也释放尚未交接的控制描述符。

### 4. 另一个确定根因：WPA2 被误判为 WEP

21:07:12.811、21:08:27.601，车机明确声明 `security=2`；紧接着却报“热点是 WEP”。
旧 Wi-Fi 代码忽略协商类型，只看密码是否为 5/10/13/26 字符；这会把合法 WPA2 密码拒绝掉。
这解释了部分自动入网失败，并非所有车都必须由用户手动连接 Wi-Fi。

修复：把安全类型从 iAP2 端点传至入网层，按类型选择 WPA2/WPA3/开放网络，不再按密码长度
猜测 WEP；记录系统连接请求退出码，开放网络的空密码也可进入正常连接流程。
